# 数据源与运行机制

## 实际触发方式

项目不是持续运行的爬虫。一次新抓取由用户、定时任务或其他自动化启动 `python scripts/run_daily.py` 触发。2.0 页面加载时只请求本地 `/api/daily`，不会访问新闻站点。

## 数据链路

1. `kpop_daily_proto.py` 请求 Soompi RSS、Google News RSS、YouTube 页面与频道 RSS，以及可用音乐榜页面。
2. 每条内容被归一成统一 Item，补齐来源、原文链接、发布时间、发现时间、类别和团体标签。
3. 相关性过滤后，用标准化标题、共同团体和字符串相似度做去重。
4. 翻译层优先调用 Google gtx，MyMemory 兜底；两者失败时保留原文。
5. `personalize_report.py` 根据内容类型与用户偏好打分，新闻取 Top N，榜单不参与新闻竞争。
6. `patch_melon.py` 尝试刷新 Melon Top 30；失败时不覆盖已有榜单。
7. `build_html.py` 把个性化 JSON 内嵌进单文件 HTML。

## “等待”具体指什么

- 单次网络请求默认最多等待 12–25 秒，取决于翻译或内容源。
- 通用抓取默认最多尝试 2 次，间隔采用指数退避并增加少量随机抖动，避免立即重复冲击同一来源。
- Melon 默认最多尝试 3 次，每次之间等待 3 秒。
- 统一入口对每个阶段设置 300 秒总上限，可用 `--step-timeout` 修改。
- 这些等待是容错控制，不是实时监听。项目没有常驻 worker、消息队列或增量推送。

## 降级原则

- 单一新闻源失败：其他来源继续，日报仍可生成。
- 翻译失败：保留原文，不伪造中文摘要。
- Melon 失败：保留抓取阶段已有的榜单；若所有榜单均失败则榜单版块为空。
- 必需阶段（抓取、个性化、HTML 构建）失败：统一入口停止并返回非零退出码。

## 定时运行

仓库只提供可被调度的命令，没有内置常驻调度器。可用操作系统任务计划、cron 或 Codex 自动化每天调用统一入口。面试中应表述为“具备定时化接口”，不要表述为“仓库已经持续实时爬取”。

## 数据源风险

Google gtx、MyMemory、Melon HTML 和 YouTube 页面解析都不是稳定的正式付费契约，可能限流或改版。生产化优先级应是：可观测性与来源健康度、正式 API/授权数据源、缓存与增量抓取、解析回归测试。
